# 关于中继服务器与隐私的说明

## 已上线小程序用到了谁的服务器?

小程序默认连接开发者自有的中继服务器。这台服务器在整个架构里**只做一件事**:在「你的手机」和「你自己的电脑」之间转发 WebSocket 帧。

```
你的手机 ⇄ (wss,加密) ⇄ 中继服务器 ⇄ (wss,加密) ⇄ 你的电脑
                                ↑
                    只转发帧,不含任何业务逻辑
```

**agent 本体(大模型调用、会话历史、文件读写)全部运行在你自己的 PC 上**——电脑关机就无法使用,就是最好的证明:服务器上没有你的任何会话数据,数据都在你自己电脑里。

## 中继能看到什么、看不到什么

诚实地说明技术边界:

- **服务器在协议上是"能看到"经过的帧的**——和所有中转服务(网关、反向代理)一样,wss 只保证"手机↔服务器"和"服务器↔你的电脑"这两段传输加密,中继进程内部路由的是明文 JSON。我们不做"技术上不可能监听"这种过度承诺。
- **但代码层面它不解析、不记录任何消息内容**:中继是纯帧路由,`src/server.mjs` 全部约 300 行开源可审计。它落盘的只有一个 state 文件,内容是设备绑定关系(token),不含会话、不含消息;运行日志只记录连接/断开/配对/绑定事件,不打任何消息体。
- **能看到并保留的元数据**:来源 IP、连接时间、配对码签发记录(用于限流与防爆破)。

如果你对任何中转方(包括我们)都不放心,下面两条路是完全公开的:审计代码,或者干脆自己部署。

## 如何部署到自己的服务器

整体分四步,详细命令见仓库根目录 README 的「快速开始」:

1. **准备**:一台能装 Docker 的 Linux 服务器、一个**已 ICP 备案**的域名、TLS 证书(域名不备案无法配进小程序合法域名,这是微信平台的硬性要求,请提前确认)。
2. **跑中继**(只绑本机,由 nginx 对外提供 https/wss):
   ```sh
   cd dsh-cloud-relay
   docker build -t dsh-cloud-relay .
   docker run -d --name dsh-cloud-relay --restart=always \
     -p 127.0.0.1:4020:4020 -v $(pwd)/state:/data dsh-cloud-relay
   ```
3. **PC 端指向你的中继**(当次生效:命令前缀;永久生效:把同一行写进 `~/.dsh/.env`,dsh 启动自动加载):
   ```sh
   RELAY_CLOUD_URL=wss://你的域名 pnpm dsh web
   ```
4. **小程序端**:注册一个自己的小程序,把 `utils/config.js` 的 `RELAY_BASE` 改成 `https://你的域名`。

## 如何注册自己的小程序(个人即可,免费)

1. 打开 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 立即注册 → 选「小程序」。
2. 主体类型选「**个人**」,用一个没注册过公众平台的邮箱即可,不需要企业资质、不收费。
3. 注册完成后在后台「开发管理 → 开发设置」拿到你的 AppID;「服务器域名」里配置:
   - request 合法域名:`https://你的域名`
   - socket 合法域名:`wss://你的域名`
4. 微信开发者工具导入 `dsh-miniprogram`,把 `project.config.json` 的 `appid` 换成你自己的。

之后扫码配对、使用,与线上版完全一致——唯一区别是所有流量走你自己的服务器。

## 一句话总结

服务器只做转发,不存会话(会话在你自己电脑上)、不记录消息内容(代码开源可查);不放心可以看代码,或者用上面四步部署一套完全属于自己的。
